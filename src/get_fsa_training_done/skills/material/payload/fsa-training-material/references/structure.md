# Document structure

What each kind of teaching document is shaped like, and every rule
`FSA material verify` applies. Both come from the same definitions the checker
executes, so nothing here is a constraint the tool does not enforce.

**Write new lecture notes as a unit.** The chapter form is older, still used by
two modules, and is recognised so those files can be checked rather than
rewritten — not because it is a choice for new work.

Universal, whatever the kind:

- Exactly one `#` heading, on line 1. No YAML front matter.
- Every fenced block declares a language. `text` is the right tag for the blocks
  that are not code — diagrams, console output, directory trees.
- Relative links resolve, and so do their `#anchors`.
- English, unless the filename ends `_vn` to mark a translation.

## Naming

- Lecture notes, handbooks and appendices: `^(\d{2})([a-z]?)_[A-Za-z0-9_&+-]+\.md$`
- Lab guides: `^[a-z0-9]+_lab_(\d{2})\.md$`
- Index `00` is the module handbook.
- Index `99` is the module appendix.
- A trailing letter marks an aside outside the syllabus (`02b_...`).
- A translation appends `_vn` to the stem.


## Lecture note (unit)

The current form, and what a new note should follow. A numbered objectives section, the concept sections, then a knowledge check and somewhere to go next.

Sections between the opening and the closing ones are numbered `1..n`, contiguously, and named by the author.

| Section | Required | Holds |
|---|---|---|
| `## Objectives` | yes | What a learner can do afterwards; verb-initial bullets. |
| `## Worked Example / Classroom Demo Flow / Complete Flow` | optional | One runnable example composing the unit's concepts. |
| `## Common Problems / Common Mistakes / Common Misconceptions` | optional | Symptoms as sub-headings, so a learner can search for the error they hit. |
| `## Practical Guidelines / Design Checklist / Review Checklist` | optional | What to do in practice, as imperatives. |
| `## Knowledge Check / Quick Check` | yes | A numbered question list, at least five, with no answers. |
| `## Further Reading / Hands-on Practice` | yes | Where to go next: primary sources, or something to build. |

`## Objectives` must open with `After this unit, learners can:`.


## Lecture note (chapter)

The older form, kept so existing modules can be checked. Prefer the unit template for anything new.

Sections between the opening and the closing ones are numbered `1..n`, contiguously, and named by the author.

| Section | Required | Holds |
|---|---|---|
| `## Objective` | yes | As above. |
| `## Sub-topic Map` | optional | A diagram of the chapter's shape. |
| `## Real-world use` | yes | Where this shows up in real work. |
| `## Self-check checklist` | yes | GitHub task-list items a learner ticks off. |

`## Objective` must open with `After this chapter, learners can:`.

Ends with A `Next:` or `Review:` line linking the sibling that follows.


## Module handbook

Slot `00`: how to study the module, what to install, what it assumes.

Sections between the opening and the closing ones are numbered `1..n`, contiguously, and named by the author.


## Module appendix

Slot `99`: the syllabus map with a link into the note that covers each outline item, plus the reference list. Largely derivable.


## Lab guide

The guided middle a session plan asks for and the corpus is missing: shorter than an assignment, step-numbered, with a checkable outcome.

| Section | Required | Holds |
|---|---|---|
| `## Objectives` | yes | The objective codes this lab serves, from the session plan. |
| `## Before you start / Setup` | optional | What must already work. |
| `## Steps` | yes | An ordered list; each step leaves something observable. |
| `## Acceptance / Done when` | yes | A task list a learner can check themselves against. |


## Fence languages

Anything outside this set is reported as a warning rather than an error — a module may legitimately introduce a language.

`bash`, `css`, `dockerfile`, `html`, `http`, `java`, `javascript`, `js`, `json`, `jsx`, `properties`, `python`, `sh`, `sql`, `text`, `ts`, `tsx`, `typescript`, `xml`, `yaml`, `yml`


## Rules — one document

Applied to every file `verify` reads.

| Rule | Severity | Checks |
|---|---|---|
| `MAT-D01` | error | The filename follows the module's naming convention |
| `MAT-D02` | error | Indexes are unique within a folder |
| `MAT-D03` | warning | Indexes run without a gap |
| `MAT-D04` | error | There is exactly one top-level heading, on the first line |
| `MAT-D05` | error | There is no YAML front matter |
| `MAT-D06` | error | The first section states what a learner will be able to do |
| `MAT-D07` | error | Numbered sections run 1..n without gaps or repeats |
| `MAT-D08` | error | The document ends with a knowledge check and somewhere to go next |
| `MAT-D09` | warning | The knowledge check asks enough questions |
| `MAT-D10` | error | Every fenced block declares a language |
| `MAT-D11` | warning | Fence languages come from the known set |
| `MAT-D12` | error | Relative links resolve to a file that exists |
| `MAT-D13` | error | Link anchors resolve to a heading in the target |
| `MAT-D14` | error | A chapter ends with a link to what follows |
| `MAT-D15` | error | A self-check list uses task-list items |
| `MAT-D16` | warning | English unless the filename marks a translation |
| `MAT-D17` | error | A lab guide has ordered steps and a checkable outcome |
| `MAT-D18` | warning | A lab guide declares its duration |

### `MAT-D01` — The filename follows the module's naming convention

The index orders the module and reserves 00 for the handbook and 99 for the appendix. A file outside the pattern sorts unpredictably and is never linked from either.

### `MAT-D02` — Indexes are unique within a folder

Two notes claiming the same position give the module two orders.

### `MAT-D03` — Indexes run without a gap

A gap usually means a note was deleted or never written; advisory because a module may deliberately leave room.

### `MAT-D04` — There is exactly one top-level heading, on the first line

It is the document's title everywhere it is listed. A second one part way down reads as a new document to every renderer.

### `MAT-D05` — There is no YAML front matter

Nothing in this corpus carries any, and a renderer that does not expect it prints the block as content.

### `MAT-D06` — The first section states what a learner will be able to do

A note that opens with content has never said what it is for, and nothing downstream can map it to an objective.

### `MAT-D07` — Numbered sections run 1..n without gaps or repeats

The numbers are how a learner and an appendix refer to a part of the note; a repeat makes a reference ambiguous.

### `MAT-D08` — The document ends with a knowledge check and somewhere to go next

Without them a note stops rather than closing, and a learner has no way to test what they just read.

### `MAT-D09` — The knowledge check asks enough questions

A check with one or two questions samples a fraction of the note.

### `MAT-D10` — Every fenced block declares a language

An untagged fence loses highlighting, and the convention is what lets `text` mark the blocks that are diagrams rather than code.

### `MAT-D11` — Fence languages come from the known set

An unrecognised tag is usually a typo; advisory because a module may legitimately introduce a new language.

### `MAT-D12` — Relative links resolve to a file that exists

A note pointing at a sibling that was renamed or never written sends the reader nowhere, and nothing reports it at render time.

### `MAT-D13` — Link anchors resolve to a heading in the target

The appendix links into specific sections; a heading rename breaks them silently.

### `MAT-D14` — A chapter ends with a link to what follows

That footer is the module's reading order.

### `MAT-D15` — A self-check list uses task-list items

Learners tick them off; plain bullets cannot be ticked.

### `MAT-D16` — English unless the filename marks a translation

A translation is a separate artifact ending `_vn`, so the original stays the thing every other document links to.

### `MAT-D17` — A lab guide has ordered steps and a checkable outcome

A lab without steps is an assignment brief, and one without an acceptance list leaves a learner unable to tell when they are done.

### `MAT-D18` — A lab guide declares its duration

The session plan allots it a number of minutes; a lab that never states one cannot be checked against that.


## Rules — material against the session plan

Applied by `coverage`, comparing a folder with the plan that asks for it.

| Rule | Severity | Checks |
|---|---|---|
| `MAT-C01` | error | Every material the session plan names exists |
| `MAT-C02` | warning | Every material in the folder is used by a session |
| `MAT-C03` | warning | A material's objective codes match the session that uses it |
| `MAT-C04` | warning | Every objective code cited is defined in the syllabus |

### `MAT-C01` — Every material the session plan names exists

The plan is a promise about what will be taught. A named file that does not exist is a session with nothing to deliver.

### `MAT-C02` — Every material in the folder is used by a session

A note nobody schedules is either unfinished or forgotten.

### `MAT-C03` — A material's objective codes match the session that uses it

The plan says which objectives a session serves; material claiming different ones is teaching to a different goal.

### `MAT-C04` — Every objective code cited is defined in the syllabus

A code the syllabus does not list is a typo or a missing objective.
