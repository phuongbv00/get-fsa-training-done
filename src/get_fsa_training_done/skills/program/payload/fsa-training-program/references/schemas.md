# File formats

Every file is UTF-8. CSVs use a comma delimiter, one header row, RFC 4180
quoting, and an **empty cell** rather than a placeholder when there is nothing
to record — "no teaching that day" and "zero hours" are different claims.

Headers are fixed and case-sensitive: they become the workbook's columns, and a
renamed one is not caught at export, it writes the wrong column.

Two of these tables end in a **derived tail** whose width depends on the
programme rather than on this tool: `W1..Wn` for as many weeks as it runs,
`D1..Dm` for as many calendar days, and one column per module in the outcome
mapping. They must run from 1 with no gaps.

## Tables

### `*_MasterSchedule`

Fixed columns, in order:

```
Semester,Topics,Module
```

Then one column per week, `W1..Wn`; the cell reads `Mark` in the module's assessment week and is otherwise empty.

### `*_DetailedSchedule`

Fixed columns, in order:

```
Semester,Topic,Module,Drt (h),Session
```

Then one column per calendar day, `D1..Dm`; a numeric cell is the hours taught that day, and weekend positions stay empty.

### `*_TopicList`

Fixed columns, in order:

```
Topic Code,Topic Name,Module,Content Group
```

### `*_OSTModuleMapping`

Fixed columns, in order:

```
Code,Evaluation category,Short Description,Description,Detail,Evaluation Method,Training Orientation
```

Then one column per module code, in the order the module table lists them; the cell reads `x` where the outcome is delivered.

### `*_ScheduleDetail`

Fixed columns, in order:

```
Unit,Training Unit/Chapter,Session,Content,Learning Objectives,Delivery Type,Duration (mins),Training Format,Training Materials / Logistics & General Notes
```


## Delivery types

A closed list. It is also the row order of a syllabus's Time Allocation table, which the workbook writes as a fixed block.

- `Concept/Lecture`
- `Assignment/Lab`
- `Guides/Review`
- `Seminar/Workshop`
- `Class Meeting`
- `Test/Quiz`
- `Exam`

Every session-plan row uses `Blended` as its training format.
